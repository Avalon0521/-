# RQ1 Pilot 评分结果与结论（6章规模，人工评分代替LLM-judge）

## 目的

验证 RQ1 实验流程（长上下文 full-context vs RAG 状态检索 story_state，对跨章节一致性错误率的影响）与指标体系（世界观违规数 / 角色OOC次数 / 伏笔遗漏率）在最小规模（6章、每章约800-1200字）下是否可执行、可测。本次为人工评分，非最终 LLM-as-judge 结果，仅用于验证流程可行性。

## 数据来源

- Ground truth: `master_ground_truth.json`（都市悬疑《雾巷》，3个契科夫的枪 G1怀表/G2老照片/G3旧钥匙，2条world_bible规则，3个角色一致性红线）
- 条件A：`chapters_A_fullcontext/ch1-6.txt`
- 条件B：`chapters_B_rag/ch1-6.txt`
- 逐条打分见 `scores_A_fullcontext.json`、`scores_B_rag.json`

## 核心结果

| 指标 | 条件A（全长上下文） | 条件B（RAG检索） |
|---|---|---|
| 世界观规则违规数 | 0 | 1（ch5老宅门变成"虚掩未锁"，绕开钥匙/私产限制的戏剧张力） |
| 角色OOC次数 | 0 | 0 |
| G1_怀表 | 部分推进，未达成大纲确认（部分遗漏） | ch1后完全未再出现（完全遗漏） |
| G2_老照片 | 提及但未深入，ch6未按计划解决（部分/完全遗漏） | ch2被文本明确降格为"普通装饰"，此后消失（完全遗漏，且引入方式已弱化其伏笔属性） |
| G3_旧钥匙 | ch2引入、ch5正确解决（完全解决，细节自创但不违反红线） | 从未引入、从未出现，ch5用"门本来没锁"绕过（完全丢失） |
| 伏笔遗漏率（3个契科夫的枪） | 约33%-67%（1个完全遗漏，2个部分完成/推进） | 100%（3个全部完全遗漏或从未引入） |
| 平均章节长度（字符） | 1487 | 947（约为A的64%，且ch3起持续走低到420-619区间） |

## 关键发现（与方案预期的对照）

1. **本次pilot结果与研究方案在2.3/3.1节的预期方向相反**：方案预期"RAG条件错误率增长更平缓"，但本次6章pilot显示 RAG 条件在伏笔遗漏率和世界观一致性上表现**明显更差**（伏笔遗漏率100% vs A条件的33%-67%，且B条件出现A条件没有的世界观规则违规）。
2. **可能的混淆因素——章节长度**：B条件平均章节长度只有A条件的64%，且从ch3开始骨架化严重（420-619字符/章，远低于ch1-2的1878/1155）。这提示一个未被方案充分讨论的风险：**当前RAG实现可能只是检索能力不足或检索结果未被有效注入drafter**，导致模型在缺少完整前文时倾向于生成更短、更简略的文本，而不是"用更精准的检索信息维持等效一致性但用更少token"。方案原假设（RAG更省token但一致性相当或更好）在本次pilot中体现为"RAG更省字数，但一致性显著更差"——两者需要区分：是检索机制本身的信息密度问题，还是当前pilot的RAG实现（可能只检索了很少的状态片段）过于简化。
3. **契科夫的枪在A/B两个条件下都未被完美处理**，即便是长上下文条件下，G2老照片也未在ch6按大纲完成揭示——说明即使给完整前文，drafter本身在"记得埋设的伏笔并在计划章节回收"这件事上也有系统性弱点，这是六章pilot规模下就能观察到的、值得在正式实验的narratology checker设计中重点关注的现象。
4. **红线一致性（角色OOC、耳背设定、不喝酒、称呼禁忌）在两个条件下均保持良好**（0次OOC），说明这类"角色层"一致性对上下文策略的敏感度可能低于"情节层"（伏笔/物件）一致性——这是本次pilot意外发现的一个可能的指标维度区分，建议正式实验中将"角色一致性"和"情节/伏笔一致性"作为两个独立子指标分别统计错误率-章节距离曲线，而不是笼统合并成一个"一致性错误率"，以避免两种误差机制的信号相互抵消或掩盖。

## 对方案的具体建议（供下一步补全）

- **正式实验前需先诊断当前RAG pipeline的检索质量**：本次pilot的B条件文本骨架化程度高，怀疑是`story_state.json`检索到的历史信息量过少或未正确注入prompt，而非"RAG机制本身导致更差一致性"这一实质性结论——建议在扩大到10-20章规模前，先输出B条件每章实际检索到的context片段做人工检查，排除"实现bug被误读为实验发现"的风险。
- **章节长度应作为混淆变量控制或至少报告**：呼应方案3.2节RQ2部分已提到的"revise可能改变文本长度需归一化"的思路，RQ1也应补充同样的控制。
- **伏笔遗漏率的判定需要更细粒度的三态划分**：本次评分中区分了"完全遗漏/部分推进未确认/完全解决"三态，比方案2.3节原定的单一"伏笔遗漏率"更能捕捉A/B条件的差异（尤其是A条件的"部分推进"现象），建议将此三态判定纳入正式的consistency checker prompt设计。

## 结论

Pilot验证流程本身可执行、指标可测（ground truth JSON + 章节文本 + 人工/LLM打分的三段式流程跑通）。但本次6章小规模结果显示的"RAG更差"方向性发现，很可能主要归因于pilot规模下RAG实现的简化/不足，而非对RQ1核心假设的有效证据——**在正式实验前必须先排查RAG检索环节的实现质量**，否则扩大规模只会放大一个实现缺陷而非验证真实机制差异。
