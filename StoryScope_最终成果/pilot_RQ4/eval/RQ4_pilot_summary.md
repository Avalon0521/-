# RQ4 Pilot 评分结果与结论（2章规模，人工模拟三种生成策略 + 人工评分代替LLM-judge）

## 目的

验证 RQ4 实验流程与指标体系——在**统一修正轮数（1轮）**的约束下，比较"全程强模型""全程廉价模型""cheap-drafter+strong-reviser路由"三种生成策略在成本-质量帕累托权衡上的可测性。RQ4 是四个RQ中此前唯一没有任何pilot素材的，本次是从零构建的最小规模验证：2章、每章约800-1500字目标量级。本次为人工模拟三种策略并人工评分，**非真实多模型API调用结果**，仅用于验证流程可行性。

## 数据来源

- Ground truth: `master_ground_truth.json`——全新构建的独立小弧段《雾巷·显影》。世界观规则复用RQ1《雾巷》设定（暗房显影/定影固定时限规则为本弧段新增的场景专属规则），角色设定复用沈知微（不喝酒红线）、周伯（耳背，本弧段不出场，仅作背景一致性约束）、陆行舟（称呼禁忌，本弧段不出场，仅作背景一致性约束），并新增专属角色顾师傅（照相馆馆主，职业保密习惯+暗房时限规则两条红线）。
- 情节独立性说明：核心物件为"老底片"（G1_老底片）与"相纸型号线索"（G2_相纸型号线索），场景为老照相馆"显影阁"——均未在RQ1（钟表铺/怀表/老照片/旧钥匙）、RQ2（挂坠符号残片）、RQ3中出现过，避免被误认为复用同批草稿或稀释既有伏笔判定样本。角色设定一致性通过共享的不喝酒红线（沈知微）在本弧段中被正面执行来体现。
- 条件A：`strategy_A_allstrong/ch1.txt`、`ch2.txt`
- 条件B：`strategy_B_allcheap/ch1.txt`、`ch2.txt`
- 条件C：`strategy_C_router/ch1/draft_by_cheap.txt` + `final_after_strong_revise.txt`；`ch2/` 同构
- 逐条打分见 `eval/scores.json`
- 成本估算与假设见 `eval/cost_estimates.json`（脚本：`eval/_compute_costs.py`）

## 方法说明（重要：诚实边界）

1. **本次pilot不涉及任何真实多模型API调用**。三种策略的文本均由本次会话人工撰写/模拟，目的是复现"强模型drafter""廉价模型drafter""廉价drafter+强reviser"在真实API调用中可能出现的**具体、可信的质量差异模式**（而非把"廉价模型"漫画化处理成明显拙劣的文本），包括：描写密度差异、专业细节完整度差异、心理独白层次差异、以及1处红线擦边的边界模糊案例（B策略ch1，沈知微在热酒摊前有约2-3秒的犹豫动作，但最终仍拒绝，未构成OOC）。
2. **成本数字是按2025-2026年公开定价量级的估算，不是实时价格，也不是真实token usage字段**。估算方法记录在 `cost_estimates.json` 的 `assumptions` 字段：中文字符数 × 1.8 系数近似估算token数；强模型定价对标 Claude Sonnet / GPT-4.1 量级（input $3/output $15 每百万token）；廉价模型定价对标 DeepSeek / Qwen 量级（input $0.15/output $0.6 每百万token）；judge/checker模型采用独立于drafter/reviser池的中间档定价（input $0.5/output $2 每百万token）。
3. Pipeline顺序复用研究方案2.2节：Drafter生成草稿 → Consistency Checker + Narratology Checker检查草稿（**两次checker调用，三种策略均需要**）→ Reviser结合issue列表生成最终文本。三种策略的checker模型保持一致（同一judge定价档），变化的是被检查草稿本身的长度和"issue列表"长度——弱草稿（B、C的cheap drafter产出）触发的checker output更长（估算280字符/次 vs 强草稿的150字符/次），这一设计直接对应研究方案"checker成本必须纳入核算"的要求，且体现了一个容易被忽略的事实：**checker成本不是常数，它会随被检文本质量系统性波动**。

| 指标 | A_allstrong | B_allcheap | C_router（评分对象为final） |
|---|---|---|---|
| 世界观规则违规数 | 0 | 0 | 0 |
| 角色OOC次数 | 0 | 0 | 0 |
| 红线边界擦边案例数 | 0 | 1（酒精场景犹豫2-3秒后仍拒绝） | 0 |

|---|---|---|---|---|---|
| A_allstrong | 0.0990 | 0.1043 | 0.0151 | **0.2184** | 6.9% |

## 关键发现

1. **路由策略C在质量上确实接近A（4/5 vs 5/5，且核心伏笔信息完整度与A几乎等量），成本却明显低于A（约为A的46%）**——初步支持研究方案"路由策略是有效的成本-质量折中"的假设方向。但差距并非"几乎没有代价"：C的ch2篇幅比A同章短31%，且具体检查发现reviser在draft的骨架基础上做的是"加固式修订"而非"重新构思式生成"——一个原本在draft和final中都存在的心理独白层被压缩成单句（对比A中保留的双层解释），这是路由策略"纠正"而非"原生生成"留下的结构性痕迹，与方案预期的"路由后可能仍略逊于全强模型"一致。
2. **C明显优于B**：核心伏笔信息完整度（G1/G2的关键线索）C与A等量，而B有实质性遗漏（手套细节丢失）；B还出现了C没有的红线擦边案例。这说明即使只用一次强reviser介入，也能把廉价drafter的骨架化文本拉回到接近强模型的红线安全水位，这是路由策略价值的一个可信证据点（哪怕n=1）。
3. **checker成本占比在B策略中高达72.7%，远高于A的6.9%和C的14.3%**——这是本次pilot意外但重要的发现：当drafter/reviser本身都用廉价模型时，**checker（判定档定价高于drafter/reviser）的成本占比会被放大**，因为drafter+reviser的绝对花费被压得很低，而checker两次调用的定价档并未跟着降低。如果实际系统中B策略被认为"几乎零成本"，很可能是因为**分析时漏算了checker成本**——这正好印证了研究方案2.1节强调的"成本核算必须纳入judge/checker本身的调用成本"这一要求的必要性：若省略checker成本，B策略的总成本会从0.0197骤降到0.0054（仅剩drafter+reviser），会让B看起来比实际更划算，扭曲三策略间的相对比较。

## 对方案的具体建议（呼应审稿意见：路由与全强策略若轮数不同会与RQ2轮数效应混淆）

- **本次pilot在设计上确实做到了修正轮数统一**：A、B、C均为"1次drafter → 1次checker组合（consistency+narratology）→ 1次reviser"的单一闭环，没有任何策略额外多跑一轮修正，checker本身也没有触发"二次修正"（即checker发现的issue全部在同一轮reviser调用中被处理，不存在"issue没改完再检查一次"的隐藏多轮）。这一点在`cost_estimates.json`的pipeline_order字段中有明确记录，可作为正式实验设计文档的对照基准。
- **但需要诚实指出一个潜在的隐藏轮数差异风险**：C策略的reviser承担的工作量在事实上比A策略的reviser更重——A的reviser是在"强drafter已产出接近成品的草稿"基础上做轻度打磨（本次估算draft_ratio=0.88，即草稿已是最终稿的88%体量），而C的reviser是在"廉价drafter产出的骨架化草稿"基础上做大幅改写/扩写（C的ch1草稿仅378字，final达1070字，扩写近3倍）。**这两种"1轮reviser"在实际工作量和token消耗上并不等价**，即使都记为"1轮"，C的reviser单次调用成本（0.0829）已经反超A的reviser调用成本（0.1043的量级接近但机制不同：A是长input+中等output，C是短input+长output）。如果正式实验只统计"轮数"而不细看"每轮的实际token消耗量"，可能会低估C策略里reviser承担的隐藏工作量，建议正式实验的成本核算表格里，除了"轮数"这一名义指标外，必须同时报告每轮的实际input/output token量，避免"轮数相同=工作量相同"的隐性误判，这也是对方案"轮数需与RQ2解耦"要求的一个延伸提醒：**轮数统一只保证了调用次数对齐，不保证每次调用的成本对齐，后者需要单独控制或报告**。
- **checker成本占比的策略间差异（6.9% vs 72.7% vs 14.3%）建议在正式实验的报告模板中固定作为一列**，而不是合并进总成本笼统呈现，因为这个数字本身就揭示了策略选择对"隐藏成本结构"的影响，是仅看总成本容易忽略的维度。

## 诚实结论

本次pilot验证了RQ4实验流程本身可执行、指标可测（ground truth JSON + 三种策略文本 + 成本估算脚本 + 人工评分的四段式流程跑通），且初步观察到的成本-质量关系方向（C接近A质量、明显优于B；A/C/B三点均不互相支配）与研究方案的假设方向一致。但必须明确以下局限：

1. **样本量n=1（每种策略仅模拟生成了1次、2章）**，且文本由人工模拟而非真实多模型API产出，质量梯度、红线擦边案例、reviser扩写幅度等具体数字都只是一次合理的模拟，不是统计意义上的发现，不能作为"路由策略优于全强/全廉价"的实质性证据。
2. **成本数字是按公开定价量级的估算代理值**（字符数×系数近似token数，且draft/final的字符比例部分为假设而非实测），与真实API调用产生的实际账单可能有数量级内但不小的偏差，仅用于验证"三种策略间成本结构差异是否可被建模和比较"这一流程环节，不用于任何绝对成本的引用。
3. 本次pilot的核心价值是**流程可行性验证**：证明了RQ4所需的四类产出物（ground truth设计、三策略文本模拟、成本核算模型、人工评分体系）可以在最小规模上被完整构建并相互对齐，为后续扩大规模（更多章节、真实多模型API调用、更大样本量）的正式实验设计提供了一个可复用的模板，而不是对"哪种生成策略更好"这一问题给出任何具有统计效力的答案。
